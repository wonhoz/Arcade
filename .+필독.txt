  1.  실행은 attract.exe 가 아니라  attract.bat            ★ 가장 중요
--------------------------------------------------------------------------------

  Attract-Mode 2.7.0 부터 attract.exe 가 콘솔 앱으로 바뀌었다.
  그냥 실행하면 이렇게 된다.

      - 검은 콘솔 창이 같이 뜬다
      - last_run.log 가 만들어지지 않는다  ->  문제가 생겨도 원인을 알 수 없다

  바탕화면 바로가기와 시작프로그램을 attract.bat 으로 바꿀 것.

    [ 직접 바꾸기 ]
      바로가기 우클릭 - 속성
        대상 :  D:\AttractMode\attract.exe   ->   D:\AttractMode\attract.bat
        실행 :  최소화

    [ 한 번에 바꾸기 - PowerShell 에 그대로 붙여넣기 ]

      $sh = New-Object -ComObject WScript.Shell
      @("$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Startup",
        "$env:USERPROFILE\Desktop", "$env:PUBLIC\Desktop") | ForEach-Object {
        Get-ChildItem $_ -Filter *.lnk -ErrorAction SilentlyContinue | ForEach-Object {
          $s = $sh.CreateShortcut($_.FullName)
          if ($s.TargetPath -like "*\attract.exe") {
            $s.TargetPath = "D:\AttractMode\attract.bat"
            $s.WorkingDirectory = "D:\AttractMode"
            $s.WindowStyle = 7
            $s.Save(); "바꿈: $($_.FullName)"
          } } }

    ※ 설치 경로가 D:\AttractMode 가 아니면 위 경로를 고쳐서 쓸 것.


--------------------------------------------------------------------------------
  2.  MAME 을 0.289 로 올리고 롬을 새 세트로 바꾼다        ★ 이번 갱신의 핵심
--------------------------------------------------------------------------------

  실행파일과 롬은 git 추적 대상이 아니라 따라오지 않는다. 작업 PC 에서 복사해 온다.

    [ 가져올 것 ]

      emulators\Mame\mame64.exe          MAME 0.289          약 302 MB
      emulators\Mame\hash\               0.289 판            약 117 MB
      emulators\Mame\roms\               새 롬 세트          약  14 GB

    [ roms 폴더 구성 ]

      roms\Arcade\           833개   MAME · MAME Vertical + 한국 정식 발매판
      roms\Arcade Adult\      56개   MAME Adult
      roms\Bios\             116개   부모셋 · BIOS · 디바이스 롬
      roms\Arcade CHD\        18개   CHD (폴더 단위)
      roms\Arcade Zinc\       31개   Zinc 용 (기존 그대로)

    ※ 기존 roms 폴더는 먼저 다른 이름으로 옮겨 두고 새 것을 넣는다.
      되돌릴 일이 생길 수 있다.

    ※ mame64.exe 를 바꾸면 hash\ 도 반드시 같이 바꾼다. 버전이 어긋나면 롬을 못 찾는다.


--------------------------------------------------------------------------------
  3.  EKMAME 은 별도 폴더로 분리됐다 (emulators\EKMAME\)
--------------------------------------------------------------------------------

  예전에는 emulators\Mame 안에 EKMAME64.exe 가 같이 있었다. 이제 나뉘었다.

    [ 가져올 것 ]

      emulators\EKMAME\EKMAME64.exe      EKMAME 0.224        약 163 MB
      emulators\EKMAME\roms\Korean\      한글화 패치 롬 39개  약 195 MB

    [ 지울 것 ]

      emulators\Mame\EKMAME64.exe        옛 0.212. 이제 안 쓴다

  ★★ roms\Korean 은 어떤 롬셋으로도 다시 만들 수 없다 ★★

      MAME 본가에 등재되지 않은 팬 한글화 롬이라 배포되는 세트에 존재하지 않는다.
      지금 갖고 있는 파일이 유일본이다. 절대 지우거나 덮어쓰지 말 것.

  ※ 설정 파일(mame.ini · plugin.ini)은 git 으로 따라온다. 손대지 말 것.
    특히 mame.ini 는 UTF-8 BOM 이 없으면 EKMAME 이 파일을 통째로 무시한다.


--------------------------------------------------------------------------------
  4.  Cemu 롬 폴더·파일 이름 맞추기            ★ 폴더만 바꾸면 안 된다
--------------------------------------------------------------------------------

  Cemu 는  <이름>\code\<이름>.rpx  구조를 요구한다.
  폴더 이름과 .rpx 파일 이름이 같아야 한다.

      emulators\Cemu\Roms\Tekken
          ->  emulators\Cemu\Roms\Tekken Tag Tournament 2

      그 안의  code\Tekken.rpx
          ->  code\Tekken Tag Tournament 2.rpx        ★ 이것도 같이

      OPU3 는 data\ 가 한 겹 더 있으면 걷어낸다
          OPU3\data\{code,content,meta}  ->  OPU3\{code,content,meta}

  롬은 git 추적 대상이 아니라 따라오지 않으므로 각 장비에서 직접 해야 한다.
  안 맞추면 Cemu 가 "Unknown file type" 오류를 내고 게임이 실행되지 않는다.

  ※ 예전 안내는 폴더만 바꾸라고 되어 있어서 .rpx 가 그대로 남아 있었다.
    그 때문에 Wii U 4개가 오랫동안 전부 실행 불가였다 (docs\ISSUES.md 66번).


--------------------------------------------------------------------------------
  5.  PSXMAME 롬 파일 이름 두 개 바꾸기
--------------------------------------------------------------------------------

      emulators\PSXMAME\roms\psyfrcex.zip   ->  psyforcex.zip
      emulators\PSXMAME\roms\sfex.zip       ->  sfexu.zip

  MAME 는 셋 이름과 zip 파일명이 같아야 롬을 찾는다.
  이 두 개는 파일명이 실제 셋 이름과 달라서 여태 실행되지 않았다
  (psyfrcex 는 그런 셋이 없고, sfex.zip 의 내용물은 sfex 가 아니라 sfexu 다).

  romlists\Zinc.txt 는 이미 psyforcex · sfexu 로 고쳐 뒀다.
  롬은 git 추적 대상이 아니라 따라오지 않으므로 각 장비에서 직접 바꿔야 한다.
  안 바꾸면 "사이킥 포스 EX" 와 "스트리트 파이터 EX" 가 실행되지 않는다.

  버튼 배열 파일(cfg)은 바꿀 것이 없다.
  bartop 은 sfexu.cfg 가 git 으로 함께 넘어왔고,
  desktop 계열 4대는 원래 sfex 계열 cfg 를 갖고 있지 않다.

  6.  Visual C++ 재배포 패키지 설치            ★ Dolphin 이 이것 없이는 안 뜬다
--------------------------------------------------------------------------------

  Dolphin 5.0-12188 은 MSVC 14.44 런타임을 요구한다.
  없으면 게임을 고르는 즉시 아무 메시지 없이 죽는다 (종료 코드 0xC0000005).

      https://aka.ms/vs/17/release/vc_redist.x64.exe

  받아서 실행하고 "다음 - 설치" 만 누르면 된다.

  ※ 설치할 때만 관리자 권한이 필요하다. 설치되면 시스템 폴더에 DLL 이 들어가고
    그 뒤로는 일반 권한으로 도는 프로그램이 그냥 쓴다.
    Attract-Mode 를 관리자로 실행할 필요는 없다. 부팅 자동 실행에도 영향 없다.

  설치됐는지는 이렇게 확인한다 (14.44 이상이면 된다).

      powershell -Command "(Get-Item $env:WINDIR\System32\vcruntime140.dll).VersionInfo.FileVersion"

--------------------------------------------------------------------------------
  7.  장비마다 확인할 것            ★ 이번 갱신에서 설정 위치가 바뀐 것들
--------------------------------------------------------------------------------

  아래 넷은 장비마다 값이 달라야 하는 것들이다. 전파할 때 이 장비의 값을
  유지하도록 처리했지만, 실제로 그런지는 한 번 확인하는 편이 좋다.

  (1) Dolphin  -  설정 위치가 바뀌었다              ★ 확인 필요

      전       내 문서\Dolphin Emulator\        (git 밖. 장비마다 따로 있었다)
      후       emulators\Dolphin\User\          (git 안. portable.txt 가 이렇게 만든다)

      저장소가 들고 있는 User\Config\ 는 작업 PC 에서 잡은 설정이다.
      이 장비에서 쓰던 컨트롤러 매핑이 따로 있었다면 옮기거나 다시 잡아야 한다.

          copy "%USERPROFILE%\Documents\Dolphin Emulator\Config\GCPadNew.ini"   emulators\Dolphin\User\Config\
          copy "%USERPROFILE%\Documents\Dolphin Emulator\Config\WiimoteNew.ini" emulators\Dolphin\User\Config\

      옛 폴더는 지우지 않았으니 언제든 꺼내 쓸 수 있다.
      portable.txt 를 지우면 안 된다. 지우면 다시 내 문서\ 를 보게 된다.

  (2) Project64  -  입력 플러그인이 바뀌었다        ★ 확인 필요

      N-Rage  ->  Project64 자체 입력 플러그인 으로 바뀌었다.
      그래서 이 장비의 Config\NRage.ini 매핑이 더 이상 쓰이지 않는다.

      N64 게임을 하나 띄워 조작을 확인하고, 예전 감이 낫다면
      Project64 설정 - 플러그인 에서 N-Rage 로 되돌린다. NRage.ini 는 그대로 남아 있다.

  (3) Cemu  -  설정 위치가 바뀌었다 (조작은 유지된다)

      emulators\Cemu\portable\ 아래에서 읽는다. 이 폴더가 없으면 %APPDATA% 를 본다.
      컨트롤러 프로필(controllerProfiles\*.txt)은 이 장비 것이 그대로 유지된다.
      Cemu 2.6 이 첫 실행 때 .txt 를 읽어 .xml 로 자동 이관한다 - 손댈 것 없다.

  (4) TeknoParrot  -  <GamePath> 가 절대경로다

      UserProfiles\*.xml 32개가 게임 exe 를 절대경로로 가리킨다.
      장비마다 설치 위치가 달라서 전파할 때 이 장비 값을 그대로 두었다.

          bartop                        D:\AttractMode
          desktop-ASUS-TUF              D:\Git\AttractMode
          desktop-MSI-Sword             C:\Git\AttractMode
          desktop-MSI-Sword-DriveWheel  C:\Git\AttractMode
          desktop                       ※ 옛 경로가 남아 있어 D:\AttractMode 로 맞췄다.
                                          이 장비의 실제 설치 경로가 다르면 아래로 고친다.

      경로를 통째로 바꾸려면 (PowerShell, <새경로> 만 바꿔서 실행):

          Get-ChildItem emulators\TeknoParrot\UserProfiles\*.xml | ForEach-Object {
            (Get-Content $_ -Raw) -replace '[A-Za-z]:\\[^<]*?\\emulators\\TeknoParrot','<새경로>\emulators\TeknoParrot' |
              Set-Content $_ -Encoding UTF8 }

      TeknoParrot 은 단일 인스턴스라 test-roms 로 연속 확인이 안 된다. 하나씩 띄워 볼 것.

  (5) Demul  -  마우스와 키보드를 꽂아 둔다             ★ 없으면 60개가 전부 안 뜬다

      Demul 의 입력 플러그인(padDemul)은 시작할 때 조건 없이 마우스 장치를 연다.
      캐비닛에 마우스가 없으면 게임마다 아래 상자가 뜨고, 닫아도 27번 반복된 뒤 끝난다.

          padDemul
          Error! (HRESULT = 80040154)
          IDirectInput CreateDevice mouse FAILED

      USB 마우스를 꽂으면 해결된다. 다만 블루투스 마우스만 꽂았을 때 같은 오류가
      한동안 계속된 사례가 있다 - 키보드까지 같이 연결하니 그때부터 정상이었다.
      유선 마우스 + 유선 키보드를 상시로 꽂아 두는 것이 가장 확실하다.

      확인:  test-roms.cmd -Launch -Emulator "SEGA NAOMI"     (40개가 전부 PASS 여야 한다)

  (6) 아트웍 파일 이름 하나 바꾸기 (menu-art 는 git 밖이다)

      romlist 의 이름 오타를 고쳤다(srtshot -> sprtshot). 아트웍은 이름으로 찾으므로
      이 장비의 menu-art 도 같이 바꿔야 그림이 나온다.

          ren "menu-art\demul\flyer\srtshot.jpg"  sprtshot.jpg
          ren "menu-art\demul\wheel\srtshot.png"  sprtshot.png

      menu-art\demul\video\sprtshot.mp4 는 이미 있으므로 srtshot.mp4 는 지워도 된다.

  8.  MAME 경고 화면 없애기          ★ exe 는 git 으로 안 따라온다
--------------------------------------------------------------------------------

  MAME 은 게임 187개에서 시작 전에 이런 화면을 띄우고 키를 누를 때까지 기다린다.

      There are known problems with this system
      에뮬레이션이 불완전한 특성: 그래픽
      아무 키를 누르면 진행합니다

  mame64.exe 에 1바이트를 고치면 안 뜬다. 이 파일은 .gitignore 대상이라
  git pull 로 따라오지 않으므로 장비마다 한 번씩 아래를 돌려야 한다.

      powershell -ExecutionPolicy Bypass -File tools\patch-mame-warnings.ps1          확인만
      powershell -ExecutionPolicy Bypass -File tools\patch-mame-warnings.ps1 -Apply   적용

  "패치됨 (EB jmp)" 이 나오면 된 것이다. 되돌리려면 -Revert.

  ※ 고정 오프셋이 아니라 시그니처로 찾으므로, 다른 MAME 빌드를 쓰더라도
    같은 코드 모양이면 그대로 찾아 고친다. 못 찾으면 아무것도 안 쓰고 멈춘다.
  ※ 확인 : 아무 게임이나 골라 경고 화면 없이 바로 시작하면 성공.
  ※ EKMAME 은 이 화면이 없다. 패치할 것 없다.

  알아두면 좋은 것
================================================================================

  * 게임을 한 번 실행하면 입력 설정·세이브가 바뀌어 git status 가 지저분해진다.

        powershell -ExecutionPolicy Bypass -File tools\reset-runtime.ps1

          인자 없이       무엇이 바뀌었는지 보여주기만 함 (안전)
          -Config -Clean  평소 정리. 설정만 되돌리고 로그·통계 삭제
          -Saves          세이브까지 되돌림  ->  게임 진행이 사라진다. 주의

  * 문제가 생기면 last_run.log 부터 본다. 레이아웃 오류·설정 경고·롬 로딩이 전부 여기 남는다.
    로그가 갱신돼 있지 않다면 attract.exe 를 직접 실행한 것이다. 1번을 다시 확인할 것.

  * 게임을 추가하거나 설정을 고쳤으면 validate.ps1 을 한 번 돌린다.

  * 공통 변경은 develop 브랜치에서 한다. 장비 브랜치에서 직접 고치면
    다른 장비로 옮기기 어려워진다.

  * 자세한 내용
        CLAUDE.md          작업 지침서 (구조·경로 규칙·작업 레시피·진단 순서)
        README.md          새 장비 설치 절차·조작키
        docs\ISSUES.md     알려진 문제와 개선 과제
